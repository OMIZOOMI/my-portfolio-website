## Corrections and compatibility

- Veyra and Adobe are first in every catalogue-derived project list; only these two are marked featured.
- Files seeds project files from `PROJECTS`; About and Browser render that same array. Terminal keeps its existing view-model shape as a derived projection, with no separate hand-written project descriptions.
- Current capabilities, status, limitations, future plans, and source evidence have separate typed fields. Existing detail layouts gain a compact scope/evidence disclosure, not a new case-study design.
- `edge-ai-hardware-state-detection` remains the file/project ID for **White Box Detection** because it already linked to the white-box repository. `cloud-native-asset-management-api` remains the ID for **Cloud-Native Task API**. `3d-macos-web-portfolio` remains the ID for **Interactive 3D Portfolio**.
- The new entries use `veyra`, `adobe-brand-audit`, `tigergraph-fraud-investigation`, and `skywatch`. Command/repository aliases resolve to canonical objects. Unknown/inherited names never resolve as projects.
- Browser address validation resolves aliases while retaining the entered URL and existing history entries. No tab IDs, history IDs, filesystem associations, or stored data are globally rewritten.
- Shared file launchers use the current catalogue title for known project IDs; the window frame also resolves retained project windows by their existing file IDs. No window identity changes are needed.
- Filesystem state remains session-only. No persistence or seed migration was added. Documents, the empty About folder, and Neural Block remain untouched.
- Approved Notes prose, camera, media, scrolling, wallpapers, sound preferences, and screen projection were not changed.
