## Technology separation and exclusions

The [hardware-state repository README](https://github.com/OMIZOOMI/hardware-state-edge-ai-detector/blob/6b56d0d999a0842d5d0eaa173bdf106d686a98a2/README.md) and its [training notebook](https://github.com/OMIZOOMI/hardware-state-edge-ai-detector/blob/6b56d0d999a0842d5d0eaa173bdf106d686a98a2/Detecting_blackbox.ipynb) were inspected only to distinguish the projects. That notebook explicitly downloads a separate modem-LED dataset through Roboflow, trains YOLOv8 Nano, and exports TFLite. It is not the white-paper-box dataset or inference program. **Hardware State is intentionally excluded from the Developer Log at Om's request.**

For White Box, OpenCV and LiteRT/TFLite inference are verified directly in `detect.py`; Roboflow and YOLOv8 Nano training are stated in that project's own README. These facts are not borrowed from the modem notebook. No accuracy figures, edge-device deployment claims, shared architecture between these two projects, or merged project narrative are introduced.

The profile README presents the task API as using AWS, PostgreSQL, and JWT security; the task API source does not substantiate those implementations. The Developer Log can speak about Om's supplied interest in cloud architecture and what backend development taught him, while avoiding those unsupported deployment/security claims.

The Adobe README identifies the competition and includes placement claims. Its repository code supports the audit's implementation, not an independently verified competition result. The revised story includes the top-45 result and approximate field size at Om’s explicit request, based on his personal account. It does not present them as independently verified by the repository review.
